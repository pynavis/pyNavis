The Data panel moves facts between Navisworks and everything around it: a point to the clipboard and back, Revit element IDs in both directions, selection sets through Excel, and saved viewpoints out to CSV.

What it does

Puts the view into a pick that runs on the native Measure tool, so the pointer snaps to vertices, edges and line ends exactly as a measurement does. The point that reaches the clipboard is the snapped one, written as X, Y, Z at three decimals in model units, which is the shape Go to Coordinates reads back.

How to use it

  1. Click Get Coordinates.
  2. Click the point. The cursor snaps as you hover.
  3. Paste wherever the point is needed: a report, a survey schedule, an email, or Go to Coordinates.

Limitations

  • Model units, not a shared coordinate system. If the model is offset from the survey grid, so is the point.
  • Esc, a right-click or picking another tool cancels and copies nothing.

Other uses

  • Report exactly where a clash is to someone who does not have the model open.

What it does

The other half of the pair. A point copied by Get Coordinates, or pasted out of a clash report or a survey schedule, is one click from being on screen. The camera keeps the direction it is already looking and only moves, standing five metres back from the point, so the angle you set up survives and the point lands in the middle of the view. A cross labelled with the coordinates is drawn on the point.

How to use it

  1. Copy a point from anywhere: three numbers separated by commas, spaces, semicolons or tabs, with or without brackets or X=/Y=/Z= labels.
  2. Click Go to Coordinates. The box opens already filled if the clipboard held three numbers.
  3. Click OK. The camera moves and the cross appears. Orbit straight away and the view turns around the point, because the focal distance moved with it.

Limitations

  • Three numbers or nothing. A comma always separates, so "1,5 2 3" is four numbers and is refused rather than read as a European decimal.
  • One marker at a time. A new point replaces the cross; Shift+Click removes it.

Other uses

  • Walk a list of survey points from a spreadsheet: copy, click, look, next row.

What it does

Selects elements by Revit element ID, in a federated model. Paste a column of IDs out of a clash report, a schedule or an email and the elements are selected in the view, zoomed to or isolated according to the settings. It looks in both places an element ID survives federation: the "Element ID" property tab an NWC exported from Revit carries, and the "[123456]" suffix a model published straight through design coordination carries in its name instead.

How to use it

  1. Copy the IDs. One per line, or separated by commas or spaces; other text between them is ignored.
  2. Click Select by IDs. The box shows the IDs it found for approval and editing.
  3. Click OK. Above one ID a progress window names the ID being looked for and offers Cancel. What is found replaces the current selection.

Limitations

  • Only real elements match. Nested parts under a family instance carry an "Element ID" tab holding the type's ID, the same number on every instance, so the tools only accept nodes the exporter marked as elements. A pasted type ID finds nothing rather than selecting the first instance of that family.
  • One ID resolves to one item by default and stops at the first hit, around a second per ID on a large model. The same element exported into two sibling files needs "Select every copy" in the settings, which is a full walk per ID.
  • Needs the exporter to have written element IDs. An NWC from a non-Revit source has none.

Other uses

  • Round-trip with Revit: IDs of Selection in Navisworks, Select by ID in Revit, or the reverse.
  • Check a list of "fixed" elements from an email against the current model.

What it does

The reverse trip. Resolves an ID for each selected item, reading it off the nearest ancestor that is a real element, because a click in the view usually lands on a geometry leaf below the element. The list goes to the clipboard, ready for Select by IDs, for Revit's own Select by ID, or for a report.

How to use it

  1. Select the items, in the view or from a set.
  2. Click IDs of Selection. The toast names a single ID or counts several, and says how many selected items carry no ID at all.
  3. Paste.

Limitations

  • Items with no element ID, such as a whole file node or non-Revit geometry, are counted in the toast and skipped.

Other uses

  • Tell a modeller exactly which elements to fix, in the one identifier both tools share.

What it does

Round-trips selection sets through an Excel workbook. Export to review a model's sets in a spreadsheet or hand them to someone, edit the rows, and import them back as new sets, or carry a library of standard sets from one federated model to the next.

How to use it

  1. Click Excel Sets and choose Export or Import.
  2. Export asks where to save an .xlsx and writes one row per search condition. A set with several conditions repeats its folder and name once per condition. A set with no conditions, including a static set, still gets a row with the condition columns blank so it stays visible.
  3. Import asks for a workbook, checks every row before touching the document, prints any problems to the output window and refuses if there are any, and otherwise creates the sets behind a progress window you can cancel.

Limitations

  • Search sets only travel as their conditions. A static set exports as a name with no conditions and is skipped on import, because its members belong to the original file.
  • Import creates new sets; it does not update sets that already exist with the same name.
  • Property names must match what the target model calls them. A set that searches for "Level" in one exporter's vocabulary finds nothing in another's.

Other uses

  • An office standard: keep one workbook of the sets every project should have and import it into each new federated model.
  • Review a model's sets without opening the model: the workbook reads as a list.

What it does

Writes every saved viewpoint in the document to a CSV file with the columns Name, Folder, Type, CameraX, CameraY and CameraZ. For an audit of what a model's saved views actually are, or to diff two issues of the same model.

How to use it

  1. Click Export Viewpoints.
  2. Choose where to save. The name offered is the document's title plus _viewpoints.csv.

Limitations

  • Animations and cuts have no camera of their own, so those rows are written with the three position columns blank rather than dropped.
  • Camera position only. Direction, section planes and hidden items are not exported; use Copy State to carry those.

Other uses

  • Compare two exports in a spreadsheet to see which views were added, renamed or moved between issues.

What it does

The settings both element ID tools share, in the panel flyout so they can be found without knowing about Shift+Click. There is one store behind them, because which property holds the ID is a fact about the model rather than about the button that reads it.

The settings

  • Property category and property, which start at "Element ID" and "Value", the tab and field the Revit exporter writes. A blank box falls back to the default rather than saving an empty value that would make every search fail silently.
  • Zoom onto what was selected, on by default.
  • Isolate, which hides everything else as well, off by default.
  • Fill the box from the clipboard, on by default.
  • Select every copy, off by default. On, it keeps walking for every copy of the element instead of stopping at the first hit, at the cost of a full walk of the document per ID.

Good to know

Open it from the flyout arrow on the Data panel title, or Shift+Click either element ID button; it is the same window.
