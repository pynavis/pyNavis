The AI panel is a beta. It puts a chat inside Navisworks that writes pyNavis tools for you: describe the button you want, read what the model proposes, click Create, and the button appears on its own AI tab. The two small buttons beside it hold the setup and the folder the tools land in. It is new and lightly tested, and it is not the only way to do this: the same authoring guide the panel gives the model can be copied into any assistant you already use.

What it does

You type what the tool should do. The panel sends that, together with the pyNavis authoring guide, to the model you chose in AI Settings. The reply comes back as a short explanation plus the files of one bundle: bundle.yaml, script.py and sometimes config.py. Nothing touches disk until you click Create tool. Then the bundle is written into AI.extension under your pyNavis extensions folder, the ribbon reloads, and the tool is on the AI tab.

How to use it

  1. Click AI Settings once, pick a provider, paste your key, and click Test until the status line says it connected.
  2. Click Ask AI to show the panel and dock it beside the view.
  3. Describe the tool in plain words. If it depends on property names, select a few representative items first and tick Attach selection: the model then sees the real category and property names instead of guessing. Names only, never values. Ctrl+Enter sends.
  4. Read the reply. View files shows exactly what would be written. If the model asked a question instead, answer it.
  5. Click Create tool. The ribbon reloads and the button is on the AI tab. Click it.
  6. Keep talking to change it: "make it also hide the rest" sends the files as they are on disk and comes back with a new version, and the card now reads Update tool. If the tool failed when you ran it, Send last error to AI pastes the traceback into the chat for a fix.
  7. New tool starts a fresh conversation. The dropdown beside it lists every tool Ask AI has made so far; pick one to continue it in a new conversation, with its files put in front of the model.

What leaves your machine

Every request carries the authoring guide and your chat so far. Only when you ticked the box, it also carries the selection summary: the item count, the category names and the property names under each, capped at a few kilobytes. Never a value: a value is project data (a source file, a client, a project number in a custom tab), so the reader does not even ask Navisworks for one. No file name, no path, no geometry, no user name. The request goes to the provider you configured and nowhere else; pyNavis has no server in the middle.

Limitations

  • Beta. Read the code before you run it. The model works from the guide and from what you say; it cannot see your model unless you attach the selection, and it cannot run the tool itself.
  • One bundle per conversation, with only those three files. The model cannot write helper modules, hooks, dock panels or icons; generated tools get a lettered icon in one of five colours, never the blue of the shipped tools, so you can always tell them apart.
  • It rewrites only tools it made, inside AI.extension. Hand-written bundles are never touched.
  • The conversation lives for the Navisworks session. Closing Navisworks forgets it; the tools stay, and the dropdown in the panel header brings any of them back for editing.
  • It takes one of the five dock panel slots.

Other uses

  • Use it as a starting point: create the tool, then open the folder and edit script.py by hand like any other bundle. Reload is not even needed for a script edit.
  • Prefer your own chatbot? Copy authoring guide in the panel's footer puts the same guide on the clipboard. Paste it, ask for the tool, and save the files it gives you into a *.pushbutton folder yourself. The authoring docs walk through that path.

Good to know

Anthropic requests send the guide as a cached prompt block, so from the second message on most of it is read from the provider's cache rather than billed in full. The Longest answer setting caps a reply; if the transcript says the answer hit the limit, raise it and ask again.

What it does

Opens the ordinary Settings window scrolled to AI assistant (beta). Two providers: Anthropic, and OpenAI-compatible, which covers OpenAI itself, Azure OpenAI, Ollama, LM Studio and most local servers through one base URL. The model is a list you can also type into. Test sends one tiny request with the values as they stand and reports what came back.

How to use it

  1. Pick the provider. For a local server choose OpenAI-compatible and set the base URL, for example http://localhost:11434/v1; leave the key empty.
  2. Paste the key. It is stored encrypted for your Windows account in %APPDATA%\pyNavis\secrets.json, never in config.json, so sharing your config or a screenshot of it never shares the key.
  3. Click Test, then Save. Ask AI uses the new values from its next message; no Reload is needed for these.

Limitations

  • The key is readable only by the Windows account that saved it. A copied secrets.json reads as "no key" on another machine.
  • Provider, base URL, model and longest answer live in config.json under ai, like every other setting.

What it does

Opens %APPDATA%\pyNavis\extensions\AI.extension\AI.tab\Generated.panel in Explorer. Every generated tool is an ordinary bundle folder there: read it, edit it, copy it into your own extension, or delete it. Before the first tool exists it says so instead of opening an empty window.

Good to know

Deleting a tool's folder and clicking Reload removes it from the ribbon. Renaming the folder changes its bundle key, so a shortcut bound to it in the Shortcuts editor would need rebinding.
