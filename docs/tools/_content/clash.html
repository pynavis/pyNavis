The Clash panel is the coordination meeting's toolkit, in the order a meeting uses it: get the numbers, group the noise into issues, fix what can be fixed on the spot, and measure the real gap where the argument is about millimetres.

What it does

Prints one row per Clash Detective test with its total and the count in each status: New, Active, Reviewed, Approved and Resolved. A line underneath totals the tests and the results. It is the number you read out at the start of the meeting, and the evidence line in the weekly report, without opening Clash Detective and adding the columns up by eye.

How to use it

  1. Run or refresh your clash tests in Clash Detective as usual.
  2. Click Clash Report. The table appears in the output window.
  3. Answer the question that follows: export the same table to CSV? Yes asks where to save it.

Limitations

  • Counts only. It does not list individual clashes; that is what the Clash Detective report and Clash Grouper are for.
  • Needs Navisworks Manage. Simulate has no Clash Detective, and the tool says so in a dialog rather than failing.
  • Groups count as one result each, the same way Clash Detective's own summary counts them.

Other uses

  • Export the CSV every week into the same folder and you have a trend line of open clashes for free.
  • Paste the table into the meeting minutes as the state of play at the time of the meeting.

What it does

Three hundred clashes between the same two runs of pipework are one problem. This tool says so before anyone opens a report. It groups a test's results into issues, either by the element that causes them or by a chain of rules you choose, shows you the groups it would make, and only then writes them into Clash Detective.

How to use it

  1. Click Clash Grouper. The dialog lists the tests in the document and fills in their result counts as it counts them.
  2. Tick the tests to group.
  3. Leave smart grouping on to group by the root-cause element, or switch it off and chain your own rules: element on side A or side B, proximity cluster, nearest level, grid intersection, source model, status, or assigned to. Rules apply in order, so "level, then element" gives one issue per element per level.
  4. Watch the preview. It shows the groups the current rules would produce, largest first, before anything is written.
  5. Click Group. The output window reports each test: how the grouping was decided, the largest groups with a link that shows the first clash in each, how many clashes were left in existing groups and how many stayed individual.

Limitations

  • Ungroup removes only the groups this tool made. Groups made by hand are never touched, which also means the tool cannot tidy up someone else's grouping.
  • Grid and level rules need grids and levels in the model. A model exported without them falls back to proximity.
  • The proximity cluster distance starts at two metres and is the setting most worth tuning: too small and one duct gets ten groups, too large and two rooms merge. It is shown and typed in the document's units, like any pyNavis length: 6' 6" in a feet-and-inches document, or a value with its unit such as 2m anywhere.

Other uses

  • Group by assigned to before a meeting so each trade sees only its own pile.
  • Group by source model to find out which link is generating most of the noise this week.

Good to know

Shift+Click stores presets in smart_clash_grouper.json; every run can still change all of them in the dialog. The groups it writes are ordinary Clash Detective groups and behave like any other in the report.

What it does

Objects clash, and the usual next step is to drag one with Item Tools until it clears, read the offset and type it into the authoring tool. This does the dragging. Select the object that should move, point at the face of it that is in the way and the face it must clear, and a prompt shows the gap as it is now and asks for the gap to leave. The object slides along those faces' normal by exactly the difference, then a dialog tells you how far, ready to type into Revit.

The same button handles the cases that are not clashes: a run of services that should sit tighter to free a corridor, or a tray that needs another 100 mm of air for a duct to pass. It moves the object towards the other face or away from it, whichever the gap needs.

How to use it

  1. Select the object that should move, say the pipe.
  2. Click Clear Clash. The native Point to Point measure opens and the banner along the bottom of the window asks for the face of the pipe that must move.
  3. Click the underside of the pipe. The banner now asks for the face it must clear.
  4. Click the top of the beam. A prompt reads "Pipe 1234 is 152.4 mm into Beam 7. Gap to leave between the two faces, in millimeters, or with a unit like 2" or 0.1m:", opening on the gap you used last time.
  5. Press Enter to keep that gap, or type another. The pipe slides up and a dialog reads "Moved Pipe 1234 by 152.4 mm".
  6. Click Copy in the dialog and paste the bare distance into the authoring tool. Ctrl+Z puts the pipe back in Navisworks.

A clash review stays at two clicks and Enter: set the gap once, and every later clash opens on it.

Pipes and conduits

Navisworks draws a pipe as a ring of narrow flat strips, and none of them is parallel to anything, so a round object is measured differently. Against a flat face, such as a wall, a beam or the underside of a duct, the flat face sets the direction and the pipe is measured to its real surface, only where it is in front of that face. It does not matter where on the pipe you click, and a sloped pipe under a beam clears at the crossing, not at its high end. Two straight pipes or conduits are measured axis to axis, less both radii, and the mover slides along the line where they come closest: straight down for two level pipes that cross. The gap between two parallel pipes on a rack is the air between them.

Limitations

  • Only the two faces are considered. A part of the object that sticks out past the face you clicked is not checked against the obstacle, and pulling an object tighter can push another part of it into something else.
  • Two flat faces must be parallel. Skewed faces are refused on the banner before the prompt opens, so you never type a number that cannot be used.
  • Two round objects work only as straight runs. An elbow, a tee or a rounded fixture against another round object is refused; click a flat face on one of them instead.
  • The gap cannot be negative. To bury one object in another on purpose, use Item Tools.
  • The move is a Navisworks transform, the same one Item Tools makes. It changes the review model only, never the source file; the number is what goes back to the author.

Other uses

  • A quick "what if": move the pipe, see whether it now hits the ceiling, undo.
  • Checking whether a tighter arrangement fits: set the gap, look, undo.
  • Sloping soffits and rotated walls work as well as floors, because the faces come from the objects' own triangles rather than the world axes.

Good to know

The prompt reads a length the way Revit does. In a feet-and-inches document that means 1' 6", 1'-6 1/2", 6 1/2", 3/4", 1.5', 18in or the space form 1 6 (feet, then inches); a bare number is in the document's own unit, and a metric value with its unit, such as 25mm, works in any document. Anything it cannot read, it asks for again, saying what it could not read.

Esc, a right-click, choosing another tool or cancelling the prompt leaves everything as it was, quietly. The last gap you gave is stored with its unit in resolve_clash.json, so 25 mm stays 25 mm in a feet-and-inches document and the next prompt opens on it. If you set a clearance with Shift+Click in an earlier version, the first prompt opens on that. There is no Shift+Click: the prompt is where the gap is set.

What it does

A rotated project makes the measure tool's X, Y and Z readouts meaningless, and the straight line overshoots whenever the two clicks are not exactly opposite each other. This reports the gap, not the line: the measured vector projected onto the faces' shared normal, which is the number a tape held square to the faces would give.

How to use it

  1. Click True Distance. The native Point to Point tool opens.
  2. Click a point on the first face, then a point on the second. Snap to corners if you like; the result is the same.
  3. Read the banner across the bottom of the window. Green: both faces found and parallel. Amber: only one face found, measured square to that one. Red: no face under either point.

Limitations

  • Both points must sit on real geometry. A point in empty space has no face.
  • Faces more than the tolerance apart in angle are reported as not parallel, with the angle, and the reading falls back to the first face.
  • The banner stays about eight seconds; the dimension drawn in the view stays until the next run.

Other uses

  • Floor to ceiling heights: horizontal faces are parallel faces too.
  • Checking a clearance someone claims was fixed, without trusting a diagonal line.

Good to know

On an imperial document the reading matches the native readout style, and the rounding fraction is yours to set. Settings live in true_distance.json.
